# VLA 파인튜닝 전략 및 데이터 준비 가이드라인
## SmolVLA 및 π0 모델 심화 분석 (인프라 맞춤형 업데이트)

---

## 1. 데이터 준비: 에피소드(Episode)의 정의 및 수집 전략

### 1-1. Raw 에피소드 데이터 공유

SmolVLA와 π0 모두 기본적으로 동일한 형식의 Raw 에피소드 데이터를 공유하여 사용할 수 있습니다. 즉, 다관절 로봇(Piper 등)을 통한 텔레오퍼레이션 수집 작업은 **한 번만 수행하면 됩니다.**

---

## 2. SmolVLA 파인튜닝 분석

### 2-1. 공식 저자 제안 수치 및 기준

| 항목 | 수치 |
|------|------|
| **최소 데이터 요구량** | 단일 태스크 기준 최소 50개의 에피소드 수집 권장 (예: 5개 초기 위치 × 각 10회) |
| **하이퍼파라미터** | 기본 사전 학습 모델 파인튜닝 시 Batch Size 64, 20,000 Steps 진행 |
| **훈련 소요 시간** | 단일 A100 GPU 기준 약 4시간 소요 (RTX 5090 적용 시 대폭 단축 예상) |

### 2-2. 커뮤니티 경험적 근거 (Hugging Face)

#### 데이터 하한선 및 분할

- **에피소드 25개 수준**: 모델 일반화에 실패합니다. 
-> 최소데이터는 25개 이상이어야함 이 이하일때 실패할 경우가 높다는 커뮤니티 의견 발견.
- **40개 데이터 분할 효과**: 동일한 40개 데이터라도 순차 분할이 아닌 **상황 기반의 층화 추출(Stratified Split)**을 적용했을 때 **성공률이 60.92%에서 87.66%로 극상승**했습니다.
-> 무슨 뜻이냐 하면 같은 erase the circle이라도 위치를 상하좌우로 옮겨서 찍은 40개의 데이터냐 아님 한 위치에 고정시킨 데이터냐에 따라 성공률이 달라짐. 위치를 옮겨서 찍은 데이터가 더 성공률이 높다는 커뮤니티 의견을 찾음.

**핵심 인사이트:**
- 데이터 양만큼 분할 방식이 중요합니다.
- 층화 추출을 통한 균형 잡힌 train/val split이 성능을 크게 좌우합니다.

## 3. π0 (Pi-Zero) 심화 파인튜닝 분석

### 3-1. 공식 저자 제안 수치 (Physical Intelligence)

| 항목 | 수치 |
|------|------|
| **최소 데이터량** | 최소 50~200개의 고품질 데모(Demonstrations) 권장 |
| **파인튜닝 하이퍼파라미터** | Batch Size 32, 3,000 Steps를 기본값으로 제시 |
| **메모리 최적화** | `--policy.train_expert_only=true` 옵션 사용을 강력히 권장 |
| **요구 리소스** | JAX 및 PyTorch 분산 학습 기준 GPU당 약 40GB의 VRAM 요구 |
| **실제 훈련 시간** | RTX 3090/4090 환경에서 50개 에피소드 파인튜닝 시 약 20~30분 |

#### 핵심 포인트

- π0는 범용적인 능력을 갖춘 로봇 파운데이션 모델로 사전 학습되었기 때문에, **최소 50개 에피소드면 의미 있는 파인튜닝 가능**
- **실무 배포 기준은 50개 이상이 안전선** (SmolVLA와 동일)

#### 메모리 최적화 상세

3B 파라미터의 VLM 백본(PaliGemma)은:
- **연산량 감소를 위해 동결**시키고
- **Action Expert 모듈만 학습**시킴으로써
- **VRAM 사용량을 대폭 절감**할 수 있습니다.

### 3-2. 커뮤니티 실무 노하우 및 실증적 한계선

#### 핵심 인사이트: 동작 자체보다 "이해력"이 병목

파인튜닝 후에도 작업 실패 시, 이는 **물리적 데이터 부족이 아니라 "장면을 올바르게 해석"하지 못하는 것**이 원인인 경우가 많습니다.

따라서 **데이터 개수를 200개, 300개로 무작정 늘리는 것보다, 기존 50~100개 데이터의 자연어 라벨링(Language Prompt)을 더 세밀하고 다양하게 다시 달아주는 것**이 성능 향상에 훨씬 직결됩니다.

#### 자연어 라벨링 다양성의 중요성

**같은 물리적 동작(Pick & Place)이라도 다양한 표현으로 라벨링:**
- "검은 큐브를 잡아줘"
- "카운터의 물체를 들어올려"
- "검은 정육면체를 왼쪽으로 옮겨줘"

이러한 라벨링 다양성이 모델의 **자연어 이해력과 일반화 능력을 극대화**합니다.

**현재 파이프라인 상황:**
- 현재 `scripts/5__record.sh`는 `--dataset.single_task=${TASK}`로 모든 episode를 동일한 task 문장으로 수집
- Parquet의 `tasks.parquet`에 **단 1개 task만** 등록됨
- 모든 episode의 `task_index`가 동일 → **자연어 다양성이 0**

**π0 성능 최대화를 위한 개선:**

1. **tasks.parquet에 여러 task 등록**
   ```
   task_id | task_description
   0       | "손으로 AIIII를 써줘"
   1       | "펜으로 글자를 따라써"
   2       | "선을 따라 쓰기"
   3       | "문자를 또렷하게 표현해"
   4       | "종이 위에 글씨 쓰기"
   ```

2. **Episode 수집 시 task 순환 할당**
   - Episode 0: task_index=0
   - Episode 1: task_index=1
   - Episode 2: task_index=2
   - ...
   - Episode 50: task_index=0 (순환)
   
   결과: **50개 episode에 5~10가지 표현 분산**

3. **Parquet 저장 구조의 변화**
   ```
   episode_index | task_index | action    | observation.images.top
   0             | 0          | [7.2, ...] | <video>
   1             | 1          | [7.1, ...] | <video>
   2             | 2          | [7.3, ...] | <video>
   ...
   49            | 4          | [7.0, ...] | <video>
   ```

4. **π0 학습 시 효과**
   - LeRobot이 자동으로 tasks.parquet에서 다양한 task 문장 로드
   - π0의 VLM이 **같은 물리 동작을 여러 언어 표현으로 학습**
   - 최종 policy가 다양한 자연어 명령어에 대응 가능

#### 학습률(Learning Rate) 제한

로보틱스 커뮤니티(EmbodiFlow 등)에서는 파인튜닝 시 모델 가중치의 붕괴를 막기 위해 **학습률을 10⁻⁵ 수준으로 낮게 설정**하는 것이 정석으로 통용됩니다.

#### 데이터 확장성 한계

OpenPI 공식 GitHub에 따르면:
- 현재 제공되는 스크립트와 LeRobot 포맷은 **'소규모 파인튜닝'에 맞춰져 있음**
- 대규모 사전 학습으로 스케일업할 시 **병목 현상이 발생**할 수 있습니다.

#### 빠른 검증을 위한 π0-FAST 활용

OpenPI 저장소의 개발자는 처음 검증을 시도할 때, 무거운 일반 디퓨전 훈련보다 **FAST 파인튜닝 방식을 먼저 시도할 것**을 권장합니다.

**π0-FAST의 장점:**
- 훨씬 빠르게 수렴
- 반복 실험 주기를 앞당기는 데 유리
- RTX 5090 환경에서 프로토타입 검증에 최적

#### 토큰화 배제 및 Flow Matching

기존 VLA가 관절 각도를 단어로 쪼개어(토큰화) 발생하는 **미세한 떨림(Jittering)을 제거**했습니다. 

연속적인 Tensor 값을 다루는 **디퓨전 기반 매칭**을 통해 사람이 원격 조종한 듯한 **부드러운 모터 궤적**을 생성합니다.

#### 다중 경로(Multi-modal) 대처

동일한 목표를 향해 왼쪽으로 가는 데모와 오른쪽으로 가는 데모가 섞여 있어도:
- 두 경로의 '평균'을 내어 충돌하는 대신
- **명확한 하나의 경로를 선택**해 수행합니다.

이를 통해 모드 붕괴(Mode Collapse) 현상을 방지합니다.

## 4. 보유 인프라 (7800X3D + 128GB RAM + RTX 5090 × 2) 적용 전략

### 4-1. 단계별 적용 전략

#### 1단계: 파이프라인 검증 (SmolVLA)

| 항목 | 내용 |
|------|------|
| **적용 모델** | SmolVLA |
| **전략 및 하드웨어 활용** | 가벼운 모델 특성을 살려 **단일 RTX 5090**으로 빠르게 학습합니다. 층화 추출이 제대로 적용되었는지, 파이퍼 로봇 암이 목표를 잘 따라가는지 **엔드투엔드 무결성을 신속히 테스트**합니다. |

#### 2단계: 고정밀 스케일업 (π0)

| 항목 | 내용 |
|------|------|
| **적용 모델** | π0 (PiZero) |
| **전략 및 하드웨어 활용** | **RTX 5090 2대를 DDP(분산 학습)로 묶어** 연산력을 극대화합니다. **VLM 백본을 동결**(train_expert_only)하여 **VRAM 초과(OOM)를 방지**하고 **Action Expert만 학습**시킵니다. |

### 4-2. 시스템 최적화 주의점

#### CPU 병목 현상 방지 (공통)

**문제:**
- 압도적인 5090의 연산 속도를 Ryzen 7800X3D(8코어)가 데이터 로딩으로 받쳐주지 못해 **CPU 병목이 발생**할 수 있습니다.

**해결책:**
- **128GB RAM을 적극 활용**해 에피소드 이미지를 메모리에 **캐싱(Caching)**하는 것이 필수적입니다.

## 5. 최종 전략 요약

### 파인튜닝 데이터 기준
두 모델 모두 **최소 50개 에피소드**를 기준으로 설정:
- **SmolVLA**: 데이터 분할 구조(층화 추출) 중심
- **π0**: 자연어 라벨링 다양성 중심

### π0 스케일업의 핵심: 자연어 라벨링 다양성

데이터 개수를 무작정 늘리기보다 **같은 50~100개 데이터 안에**:
- 로봇의 환경 다양성 (조명, 객체 위치 변화)
- 지시어의 표현 다양성 ("컵 집어", "검은 컵 잡아", "왼쪽 컵을 오른쪽으로")

이 두 가지를 **밀도 있게 욱여넣는 것**이 성공의 핵심입니다.

**현재 파이프라인 개선 로드맵:**

| 단계 | 현재 상태 | 목표 상태 |
|------|---------|---------|
| **Task 정의** | 1개 고정 ("write AIIII") | 5~10개 자연어 표현 등록 |
| **Episode 할당** | 모두 task_index=0 | task_index를 순환하며 할당 (0→1→2→...→0) |
| **Parquet 구조** | tasks.parquet에 1행만 | tasks.parquet에 5~10행 (각 표현별) |
| **π0 학습 입력** | 동일한 명령어만 반복 | 다양한 자연어 표현으로 학습 |

### 보유 인프라 (RTX 5090 × 2) 활용 전략

1. **1단계**: SmolVLA로 파이프라인 + 데이터 검증 (단일 5090, 빠름)
   - 현재 기본값 유지 (배치 8, 5k steps)
   - 위치 다양성 검증

2. **2단계**: π0 준비 (수집 파이프라인 개선)
   - `scripts/5__record.sh` 수정: `--dataset.single_task` 제거
   - tasks.parquet에 5~10개 자연어 표현 사전 등록
   - Episode 수집 시 task_index를 순환하며 할당
   - **같은 50개 데이터에 자연어 다양성 추가**

3. **3단계**: π0로 고정밀 학습 (DDP 2×5090, π0-FAST 권장)
   - 자연어 다양성이 반영된 dataset으로 학습
   - π0-FAST로 빠른 반복 실험
   - 메모리 캐싱으로 CPU 병목 제거

### 핵심 정리

| 항목 | SmolVLA | π0 |
|------|---------|-----|
| **최소 데이터** | 50개 에피소드 | 50개 에피소드 |
| **성공 핵심** | 데이터 분할 균형 (위치 다양성) | 자연어 라벨링 다양성 (task 표현 다양성) |
| **훈련 시간** | A100 4시간 | RTX 3090/4090 20~30분 |
| **학습 전략** | 배치 64, 20k steps | 배치 32, 3k steps (또는 π0-FAST) |
| **최적화** | 계산량 중심 | 메모리 + 이해력 중심 |
| **파이프라인 수정** | 위치를 상하좌우로 변화 | tasks.parquet에 5~10개 표현 등록 + task_index 순환 할당 |
